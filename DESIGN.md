# ClaimAgent — scoped claim workflows

## Scope
The maintained scoped surfaces are:
- งานเคลม > ค้นหาเคลม > ดูรายละเอียด > รายละเอียดเคลมลูกค้า
- งานเคลม > ค้นหาเคลม: Search / Result / Policy Selection / Claim History
- พิจารณาเคลม > เคลมโรงพยาบาล > บันทึกข้อมูลเคลม (Step 1), limited to traffic-accident information and document-check columns/validation
- วางบิลเคลม > เคลมโรงพยาบาล > ตรวจสอบรายการวางบิล (Step 1), limited to removing document result and note columns from ตรวจสอบเอกสาร
- พิจารณาเคลม > เคลมลูกค้า และวางบิลเคลม > เคลมโรงพยาบาล (Step 1), limited to the shared traffic-accident information section

The current user requests define these scoped hospital-claim changes. งานเคลม > ค้นหาเคลม > ดูรายละเอียด uses the native read-only customer detail surface within the existing application shell; the late compatibility patch forwards to this renderer and does not blank the body. Existing edit, notification, shared navigation, and all unrelated billing and consideration surfaces retain their behavior.

งานเคลม > ค้นหาเคลม uses an adaptive search surface scoped by `#claimWorkSearchSurface`. It supports eight search types: CL and Case return claim-level results; insured identity returns person and policy choices; duplicate names require person selection; school searches include academic year. Selecting a policy reuses the existing Claim History renderer. The shared แจ้งเคลม > ค้นหาการแจ้งเคลม surface remains legacy and unchanged. Search CSS, behavior, and mock data live in separate classic-script files and do not consume `claimMonitorRows`.

The approved Claim Search visual reference uses primary `#1458d6`, secondary `#2f7df3`, soft blue `#eaf2ff`, line `#dfe8f2`, text `#10243e`, and muted `#6d7d90`. Thirteen search examples cover all eight search types plus approved/waiting-document/rejected Claim states, a single insured with several policies, a duplicate name, and another school. They remain a single internally scrollable chip row on desktop and mobile. Duplicate-name results reuse the insured summary and policy-table pattern used by national-ID results, grouped once per matching person, instead of introducing a separate card-only chooser. Claim History uses the same scoped blue visual language only when entered from งานเคลม > ค้นหาเคลม. Its desktop insured Hero is capped at 164px while preserving two readable information rows; App status uses explicit active/pending/closed contrast tones. Claim-level result actions use a compact square visibility Icon Button with a claim-specific accessible name and tooltip.

## Visual direction and runtime ownership
Reuse the existing blue claim header and Material icons. The customer detail is an isolated MUI 5 surface; no global CssBaseline or shared theme changes. Runtime tokens are in `js/menu-customer-claim-detail.js`; geometry and legacy typography containment are in `css/customer-claim-detail.css`, scoped to `#customerClaimReadOnlyPage`.
Existing system font via `var(--ui-font)` (TH Sarabun New / TH SarabunPSK / Sarabun). The approved Claim Detail direction follows the v14 reference tokens: primary `#1458d6`, secondary `#2f7df3`, soft blue `#eaf2ff`, line `#dfe8f2`, text `#10243e`, muted `#6d7d90`, success `#15925c`, and warning `#d98216`. Its signature is a dark-to-bright blue claim cockpit: read-only context strip, explicit mock notice, identity/claim hero, icon-led summary strip, consideration-style section tabs, separated section cards, and emphasized financial cards. The section tabs mirror `.customer-review-tabs`: subtle white-to-blue strip, blue active underline, soft-blue hover, and horizontal scrolling on narrow screens; their behavior remains scroll-to-section. Approved net is the largest text. Document scrolling remains the page owner; horizontal scrolling belongs to context strips, navigation, financial summaries, and tables at narrow widths.

## Data and behavior
PH omits school, insured type, and student insurance card. PA includes these and shows the school name in the hero. Claim status, decision, payment status, approved net, and transferred amount remain distinct. Explicit detailed records preserve missing amounts as an em dash and zero as 0.00. Per the follow-up user request, sparse legacy demo records receive realistic view-only sample details, clearly labeled ข้อมูลตัวอย่าง. Mock expense rows reconcile with financial totals; Exgratia is already included in approved net. Existing source records are never mutated.
Read-only MUI Typography, Chip, Paper, Table, and Button are the owners for this surface. Back restores the prior page, scroll and focused control. Section links scroll to headings. Documents with a supported URL open for viewing in a new tab; documents without a file state that explicitly. Mock documents open an accessible MUI Dialog preview with matching claim data and an explicit sample label. There are no save/upload/delete/decision actions.
The billing hospital document-check table is a four-column lookup surface: document item, document search, document count, and details. Per-document result and note remain out of this billing section for every hospital claim type; shared consideration screens keep their existing columns and behavior.
Traffic-accident information uses one shared responsive card across hospital consideration, hospital billing, and customer consideration. Hospital consideration and billing show preselected source/default values as disabled controls. Customer consideration starts with the traffic-accident qualifier set to `ไม่ใช่`; choosing `ใช่` reveals the editable detail groups and makes their required-field validation active before leaving Step 1.
Its approved visual reference uses a compact pale-blue full-width header with a car icon, strong Thai title and muted subtitle, followed by three equal columns separated by vertical rules. Radio choices stack vertically without pill containers, using readable 19px labels and compact 6px row gaps; the driver reminder is an inline amber information icon with text. The card has no forced column height; below 820px the columns stack with horizontal separators.
